# Setup Checklist

Use this checklist before the team starts building heavily.

## Repo Setup

- [ ] Add all teammates as GitHub collaborators.
- [ ] Confirm everyone can clone, branch, push, and open a PR.
- [ ] Decide whether direct pushes to `main` are allowed. Recommended: use PRs for all code changes.
- [ ] Turn on branch protection for `main` if the team wants stricter review rules.
- [ ] Create labels for `frontend`, `backend`, `ai`, `docs`, `design`, `bug`, and `urgent`.
- [ ] Create issues for the first batch of tasks.

## Project Decisions

- [ ] Finalize the SIH problem statement.
- [ ] Write the one-sentence solution goal.
- [ ] Decide the MVP features.
- [ ] Decide what will be shown in the final demo.
- [ ] Choose the tech stack.
- [ ] Decide who owns frontend, backend, AI/data, design, docs, and integration.

## Development Setup

- [ ] Add the app scaffold.
- [ ] Add setup commands to `README.md`.
- [ ] Add required environment variable names to `.env.example`.
- [ ] Confirm the app runs on every teammate's machine.
- [ ] Add a simple test or smoke-check command.
- [ ] Decide the deployment target if a live demo is needed.

## Demo And Submission

- [ ] Write the demo script.
- [ ] Prepare sample data or demo accounts.
- [ ] Capture screenshots for the pitch deck.
- [ ] Create the final architecture diagram.
- [ ] List known limitations honestly.
- [ ] Rehearse the demo end to end.

## Daily Rhythm

Suggested rhythm during the hackathon:

- Start: decide tasks and owners.
- Midpoint: integrate early and check blockers.
- Evening: merge stable work and update docs.
- Final day: freeze features early, polish demo, and fix only high-impact bugs.
