# Team Roles

Use this as a starting point. The team can adjust roles once the problem statement and stack are final.

## Team Lead / Integrator

Owns coordination and final integration.

Responsibilities:

- Keep the team focused on the MVP.
- Break work into small tasks.
- Track who owns each task.
- Review pull requests or assign reviewers.
- Keep `main` stable before demos and submissions.
- Make final calls when scope needs to be reduced.

## Product / Research

Owns the problem understanding and user value.

Responsibilities:

- Read the SIH problem statement carefully.
- Identify users, pain points, constraints, and success metrics.
- Keep the feature list realistic for the hackathon timeline.
- Make sure the demo explains why the solution matters.
- Capture important assumptions in the README or docs.

## Design / UX

Owns the user journey and visual flow.

Responsibilities:

- Sketch the main user flow before coding begins.
- Define the key screens needed for the demo.
- Keep UI copy clear and simple.
- Share wireframes or screenshots with frontend teammates.
- Help prepare demo visuals and presentation flow.

## Frontend

Owns the user-facing app experience.

Responsibilities:

- Build screens and UI components.
- Connect screens to backend or mock data.
- Handle loading, empty, and error states.
- Keep the app usable on the demo device.
- Add screenshots to PRs for visual changes.

## Backend

Owns the server-side system and data flow.

Responsibilities:

- Design APIs and data models.
- Implement integrations and authentication if needed.
- Keep secrets in environment variables.
- Document required environment variables.
- Make local run commands clear for the team.

## AI / ML / Data

Owns intelligent features, model behavior, and data handling.

Responsibilities:

- Prototype model, prompt, retrieval, or data logic.
- Keep experiments reproducible.
- Document datasets, sources, and limitations.
- Define simple evaluation checks for the demo use case.
- Coordinate with backend/frontend on API shape.

## Documentation / Pitch

Owns submission material and storytelling.

Responsibilities:

- Keep README and setup docs current.
- Maintain the demo script.
- Prepare pitch deck content.
- Capture screenshots, architecture diagrams, and final features.
- Make sure the submission explains impact, feasibility, and novelty.

## Working Agreement

- Every task gets one clear owner.
- Shared decisions go in docs or the README.
- Large decisions should be discussed before implementation.
- During crunch time, prefer working software over extra features.
